# Technical architecture

## Platform
Native SwiftUI iOS 17+ baseline; verify deployment and toolchain requirements before release. Portable LightingCore Swift package for domain logic. App/ is the composition/UI layer. XcodeGen produces a reproducible Xcode project. Prefer Apple frameworks, limited dependencies with documented licenses, no embedded keys.

## Boundaries
- LightingCore: value-type scene, SI units, validation, ideal photometry, deterministic fixtures. Current ideal emitter frames, directional/rectangular photometry, camera geometry, ideal Planckian/Bradford color pipeline, relative neutral-card exposure and schema v4; future modules include calibrated camera response/color/exposure, equipment distribution and solver contracts. No Apple UI/AR dependency.
- Studio rendering: RealityKit for scene interaction/AR shared representation; use Metal custom shading where necessary for physical fidelity. Keep adapter separate from domain; use scene-linear radiance, explicit exposure/white balance/tone mapping and consistent coordinate transforms. Distinguish candela, lumen, lux and electrical watts. Do not equate watts with luminous output; calibrated equipment profiles include provenance and uncertainty. Area-source integration/soft shadows require numerical validation; point-source estimate is not a softbox simulator. Current Study CPU oracle traces a neutral sphere and finite panel, with direct diffuse/GGX response and deterministic 8×8 or 32×32 finite-emitter samples, visibility, and relative color. An optional Metal Float32 kernel consumes the same validated packed sample/camera/white-balance data; runtime parity checks six known fixtures before selecting it and falls back to the Double CPU oracle. A portable C++ harness executes the shared math against the Swift oracle, not the actual GPU. SceneKit Plan/3D remains illustrative; production RealityKit interaction, realistic subject/materials and calibration remain outstanding.
- Editor: SwiftUI state on main actor, stable IDs, commands/undo, normalized values, selection, inspector, accessible numeric controls; move expensive work off main actor, cancel stale tasks.
- Reference: PhotosPicker, Vision/Core ML/Core Image, orientation and color management, optional user annotations. Model output is untrusted; validate ranges, rank multiple plausible rigs, abstain on ambiguity. Never infer identity or upload images by default.
- AR: ARKit world tracking, session lifecycle, interruption/relocalization, capability checks, explicit transforms, tracking confidence. RoomPlan optional on supported LiDAR devices. Do not invent placement accuracy.
- Persistence: versioned Codable JSON, atomic writes, app-private storage; upgrade to project library with migrations, thumbnails, safe import/export, recovery, and explicit deletion. No silent overwrite on decode failure.
- Commerce: StoreKit 2 nonconsumable verified entitlements, transaction updates, restore, offline behavior and sandbox tests. No paywall gating before valid implementation.
- Export: vector diagram/PDF and share sheet, accessible legend, units, source provenance, project version.

## Coordinates and color
Right-handed scene coordinates, meters: +x right, +y up, +z toward camera for initial default; view adapters handle transforms explicitly. Orientation conventions must be documented and unit-tested. Point source ideal illuminance E = I cos(theta) / r² on a surface, with bounded physically valid domain; implemented with explicit receiver orientation and normalized direction, cosine directional falloff and bounded finite Lambertian rectangle integration. Camera uses 36 × 24 mm sensor, 14–200 mm focal length, local forward −Z and ideal perspective. v1/v2/v3 scenes migrate to v4 with legacy optics, lens and default card settings preserved. Light spectra are ideal blackbodies normalized to photopic Y; direct lux-weighted XYZ is transformed with Bradford white adaptation, relative stop scaling, luminance Reinhard tone mapping and neutral-axis gamut compression to sRGB. The card is a diagnostic 18% reflectance with a 1000 lx reference, not a measured camera response; relative exposure does not change lux. Current SceneKit adapter approximates lighting and requests the ideal vertical FOV in a 3:2 viewport; neither rendered photometry nor native framing output is calibrated or verified. Color temperature in Kelvin is not a complete spectral model. Keep photometric calculations separate from RGB display and test exposure and monotonicity.

## Security
Use least privilege, clear permission purposes, no analytics by default, no secret logging, no photo data in telemetry. Treat imported files and model output as untrusted; bound input sizes, validate schema, handle corruption and cancellation. External inference is an explicit future decision with consent, data retention and cost limits.
