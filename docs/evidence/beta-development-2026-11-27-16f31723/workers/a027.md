## Disposition

`StudioEditorState.swift` repairs selection after scene changes, cancellation and history movement. It retains a still-live UUID, selects the first surviving light when the selected one is removed, and clears selection for an empty rig. Undo restoring a deleted light therefore does not steal an existing valid selection. Invalid selection requests leave the current selection and history untouched.

Validated no-op commands and selection-only changes preserve the revision. Real changes, Undo/Redo and changed rollback issue fresh identities; an edit followed by Undo cannot revive a stale feature receipt. Validation precedes mutation, including complete-scene replacement. Continuous out-and-back edits restore original optional representations and preserve the old redo branch while retaining the newer revision.

`SceneEditHistory.swift` commits a different owner before beginning its transaction, ignores mismatched late ends, retains the original start for repeated begins, and keeps both directions bounded to at most 60 snapshots. Discrete commands during a gesture remain separately undoable. The history primitive can finalize an active transaction for Undo, while the editor deliberately rejects Undo/Redo during editing; existing editor tests establish that boundary.

Project adoption with history reset clears pending transactions and both history directions, chooses the new first light and retires revision. Save/metadata adoption cannot replace the live scene while preserving old history. `StudioSession` additionally qualifies callbacks with generation and changes presentation identity on workspace replacement; first save preserves the same document's control ownership.
