## Confirmed gap and change

`ComparisonSessionDismissalObserver` previously ran cleanup only when `viewDidDisappear` followed a UIKit ancestor dismissal. SwiftUI removal or parent teardown does not require that dismissal flag, so that path lacked an explicit cancellation/clear callback. The observer serves both `PhotoComparisonView` and `ReferenceComparisonView`; their existing cleanup cancels imports, invalidates request identities and clears retained images (plus reference analysis).

`App/PhotoComparisonView.swift` now invokes the same cleanup through `dismantleUIViewController`. Controller cleanup is terminal and idempotent, releases its captured callback before invocation, tolerates reentrant teardown, and rejects late callback updates. Ordinary disappearance under a nested picker still does not end the session. Existing explicit Done/accepted-Apply cleanup and cancelled interactive-swipe handling are preserved. No ReferenceComparisonView source edits were needed.

Two focused methods in existing `NativeTests/ReferencePhotoTests.swift` cover temporary disappear/reappear followed by removal, exactly-once reentrant cleanup, captured-resource release, rejected late callback retention, and late lifecycle events. No new test file, package exclusion, UI shard or project configuration change.
