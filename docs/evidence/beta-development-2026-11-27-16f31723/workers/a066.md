## Disposition

**No demonstrated Release or shared text-recorder privacy defect; one diagnostic-disclosure omission.**

`StudioTextField.swift:483–622` places both collection and the complete recorder inside `#if DEBUG`. Explicit `KEYFILL_UI_TEXT_INPUT_TRACE=1` enables bounded metadata only: allowlisted field names, temporary control/lifecycle IDs, event sequence, wall-clock time, flags and capped UTF-16 lengths. Unknown identifiers become `other`; raw draft/replacement/label/hint text, photos, paths and system uptime are absent. The 512-process/256-control budgets include terminal markers and prevent further state collection.

Layout probes additionally require `-ui-testing` plus `KEYFILL_UI_TEXT_LAYOUT_PROBES=1`. Production probe names are fixed; emitted accessibility values contain geometry, not text. Release view modifiers are inert, although shared transport types/helpers remain compiled.

**Inventory gap:** `docs/PRIVACY.md:21` describes only the shared text recorder. `StudioSlider.swift:259–272` separately enables DEBUG slider logging through `-ui-testing` and `KEYFILL_UI_TEST_SLIDER_TRACE=1`, actually set by `StudioOpticsUITests.swift:98`. It emits the current fixed control identifier, numeric display/model values and state, capped at 64 per control without a process cap. Document this separate path and layout-probe switch; do not generalize the text recorder’s fields/flag/budgets to all diagnostics. This is an opt-in developer disclosure issue, not evidence of a Release leak.

## Proposed disclosure

Alongside the shared text recorder’s limits of 512 records per process and 256 per control, DEBUG layout probes require `-ui-testing` plus `KEYFILL_UI_TEXT_LAYOUT_PROBES=1` and expose fixed names/geometry. Separate DEBUG slider logging requires `-ui-testing` plus `KEYFILL_UI_TEST_SLIDER_TRACE=1`, recording fixed control identifiers, numeric display/model values and state: 64 records per native slider object, without a process cap.
