The existing implementation already handles the major beta risks in this scope:

- Provider access remains security-scoped across `NSFileCoordinator` materialization and accessor execution. The reader uses the coordinator-supplied URL and propagates coordinator errors.
- Cancellation reaches both the detached worker and coordinator, including cancellation before coordinator installation. Publication rechecks caller cancellation. Importing never mutates the selected file.
- The opened descriptor is authoritative: `O_NOFOLLOW`, `O_NONBLOCK`, `fstat`, regular-file validation and a byte cap prevent final-symlink/FIFO reads and oversized materialization. Growth after metadata inspection is bounded to one extra byte. Reads recheck cancellation between 64 KiB chunks.
- Backup preparation captures an immutable name/scene, performs encoding in a detached task, propagates task cancellation and retains its prepared document while the system exporter is using it. Success/failure text does not change library data; user cancellation does not claim a save.
- The import consumer validates its request identity and unchanged scene before reserving a create operation, rejects late results after dismissal, and keeps a committed storage operation under the Studio owner's lifetime.

Existing native regressions explicitly exercise coordinated round-trips, oversized files, nonregular files, pathname replacement, growth during reads, source preservation, actual task cancellation, coordinator errors, and held file-presenter cancellation.
