## Changes

`App/SceneArrangementView.swift` and `App/LightTargetLuxView.swift` now require a Boolean acceptance result from their application callbacks. Both editors previously marked themselves complete and dismissed even when the session rejected an invalid or stale proposal.

Each editor still sets its existing completion guard before invoking the synchronous callback, preventing reentrant application. When the callback rejects the change, the editor restores the guard, retains all entered values, and displays inline feedback explaining that the draft remains available with retry/reopen actions. Only accepted changes dismiss the editor. Existing model validation errors retain their previous behavior.
