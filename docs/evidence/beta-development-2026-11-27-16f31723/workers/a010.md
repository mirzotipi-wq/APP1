# A010 — unsaved-edit recovery design

**Assessment only.** Source inspected through local `a01fa08`; campaign baseline `14d33cd`. No code changes, tests, network requests or worker launches.

## Existing behavior

`StudioSession` retains unsaved scenes in memory. `StudioView` closes editing groups on inactive/disappear but does not checkpoint them. `ProjectStore` writes explicit library operations only. Existing `saveRecoveryCopy` rescues a still-live conflict draft; unreadable-library recovery preserves saved-file bytes before starting over. Neither restores unsaved edits after process termination. Saved data is protected by the existing whole-library compare-and-save lock; retain that contract.

## Recommended smallest coherent slice

Add a separate, local recovery envelope per window/document session under `KeyAndFill/UnsavedDrafts/<UUID>.json`. It must never replace `projects.json` or make the UI claim the project was saved.

**Envelope:** schema version, draft UUID, process/session UUIDs, monotonically increasing sequence, checkpoint date, optional source project UUID, bounded display name, validated `LightingScene`, and one preallocated recovered-project UUID. No photo, undo history, raw numeric drafts, device identifiers or full library snapshot. Restore always creates a separate project, so source identity is context rather than overwrite authorization. Cap the encoded envelope at 2 MiB, including metadata; `SceneCodec` already caps scene documents at 1 MiB.

**Lifecycle:** checkpoint accepted scene revisions after a short debounce, at completed edit transactions, and immediately on background transition. Capture immutable values on the main actor; serialize writes off it. Every write, cleanup and retirement carries the sequence. A delayed older write cannot recreate a deleted clean draft. Clear only after a successful save receipt matches that checkpoint’s scene/document, or explicit discard. Failed saves retain recovery data. Background saving is best-effort; report checkpoint failure without falsely guaranteeing crash recovery. Do not use `onDisappear` as permission to discard.

**Multiple windows:** allocate a fresh session UUID per editor. Maintain an in-process registry of live owners and exclude their drafts from recovery choices; one window must not claim another live window’s work. Compare the observed envelope’s identity/sequence before restore or discard. New windows never share a filename. An old process’s files become candidates on relaunch.

**Restore:** offer a nonmodal “Unsaved work available” entry after ordinary library load, with name/date/light-count review and explicit “Save as recovered project” or confirmed “Discard.” Require the current editor to be clean before switching. Append to the latest validated library through its existing transaction lock, using the envelope’s preallocated recovered-project UUID. `ProjectLibrary.create` already accepts an explicit ID. If that ID already exists after a crash between commit and cleanup, do not create another copy or overwrite it. Remove only the observed envelope after a committed receipt; capacity, corruption and write failures leave it intact. Unsupported envelopes remain available for explicit export/discard, never silent deletion.

**Retention:** at most 16 envelopes / 32 MiB initially, with bounded enumeration and reads. At capacity, preserve older work and surface recovery management; do not silently evict unsaved work by age. Successful save/recovery and confirmed discard release capacity. Document the added local retention in privacy/settings copy.

## Ownership and verification

1. Core owner: new `RecoveryDraft.swift`, `RecoveryDraftStore.swift`, narrowly scoped idempotent recovery insertion in `ProjectLibrary.swift`; focused atomic-write, malformed-input, stale-sequence and capacity checks.
2. Orchestration owner: `ProjectStore`, `StudioSession`, operation receipt types; racing save/checkpoint/delete, two-window ownership, failed-save retention and restart recovery.
3. UI owner: dedicated recovery view plus `StudioView` lifecycle wiring; explicit review/discard, large text and blocked-library behavior. Root coordinates package inclusion and privacy documentation.

**Recommendation:** valuable next persistence slice, but not a quick background-Save patch. In this environment, implement only if the full slice and meaningful Swift/Apple verification can be completed. Shipping an unverified journal would add a second data-loss surface; finish the current bounded beta fixes first and keep this as a separately reviewed checkpoint.
