## Concrete defect and repair

The Reference Apply confirmation previously called `closeSession()` before a `Void` parent callback. `closeSession()` canceled import/analysis and erased the in-memory photo, observations and candidate rigs. The parent can reject application because its feature receipt is stale, invalid or busy. Such rejection therefore lost the user's entire reference session even though the studio remained unchanged.

The view callback now returns `Bool`. It asks the session to admit the selected rig first. A false result keeps the photo, analysis, observations and selected proposal in place, leaves the sheet open, and shows an inline error beside Apply. Only a true result clears and dismisses the session. Changing/rebuilding a proposal or explicitly trying again resets the previous Apply message. Explicit Done/Remove, successful replacement and successful Apply preserve their existing cleanup behavior.

Root must integrate the corresponding `App/StudioFeatureSheets.swift` callback change: return `false` on rejection, call `onReferenceApplied()` only on success, then return `true`. Repository search found this is the only `ReferenceComparisonView` constructor call. The private commit alone intentionally requires that coordinated composition change.
