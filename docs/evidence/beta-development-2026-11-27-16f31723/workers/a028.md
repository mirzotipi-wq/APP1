## Implemented

Settings now shows the complete source revision from immutable `Bundle.main` metadata, or **Unavailable**. The monospaced value supports selection and vertical wrapping, with accessibility identifier `buildSourceRevision`.

`BetaFeedbackReport` adds a backward-compatible final initializer argument `sourceRevision: String? = nil` and immutable optional property. Shared `validatedSourceRevision(_:)` inspects at most 41 UTF-8 bytes, requires exactly 40 ASCII hexadecimal bytes, and canonicalizes case. Missing values, unresolved build settings, abbreviated hashes, whitespace, injected text and oversized input are rejected. No source revision is guessed from app version, runtime environment or current files.

Valid metadata adds one report line after Device family and a matching disclosure in the draft and shared text. Metadata lines 2–5 stay unchanged. Invalid or absent metadata produces the original no-revision report exactly. No photos, project contents, paths, hardware identifiers, account details or logs were added.

Two focused portable regressions cover canonical full identity, distinct sources sharing the same app version/build, and invalid/absent/oversized metadata preserving the existing report. The existing maximum-report case now includes source metadata. The UI exact fixture independently obtains its expected revision from the UI-test bundle; it cannot derive expected identity from the report under test. All prior exact fields and privacy checks remain.
