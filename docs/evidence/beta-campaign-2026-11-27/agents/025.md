Occupied archive roots, symlink archive roots, invalid replacement schema, and changed existing sources already have regression tests; those were not duplicated. Existing OS fault probes exercise ordinary `save`, not `recoverUnreadableLibrary`.

Added two deterministic tests for previously untested recovery invariants:

1. A model-valid replacement with more than 8 MiB of encoded JSON must fail with `tooLarge` before creating an archive or mutating any source. Both existing-library and legacy-only fixtures verify exact bytes, unchanged complete recovery snapshots/file identities, unchanged directory entries, and continued absence of the primary destination when appropriate. Retrying a bounded candidate with the same confirmation must succeed, retain exact originals, and create exactly one archive.
2. A legacy-only confirmation that observed no `projects.json` cannot overwrite a subsequently created multi-project library. The stale rejection preserves its exact bytes/active identity/records, retains the corrupt legacy bytes, and creates no recovery archive.

No production correctness defect was established. These are additional regression guards, not evidence of injected OS write failures.
