## Prioritized findings

1. **P1 beta recovery gap: persistent corrupt-load failure has no usable recovery route.** `App/StudioView.swift:69–83` offers only Retry; Projects/import and export are disabled at `:298–313`. `App/StudioSession.swift:345–350` keeps a failed initial load blocked. Reproduce with the existing `-ui-testing` + UUID `KEYFILL_UI_TEST_ID` + `KEYFILL_UI_TEST_CORRUPT=1` fixture (`App/ProjectStore.swift:93–100`), or an invalid existing projects file. Repeated loading cannot repair deterministic corruption, and a user holding a valid editable backup cannot reach its importer. This is source-confirmed recovery incompleteness, **not evidence that the app corrupts data**. Add an explicit preservation-first recovery flow: retain the original bytes, report the failure, allow validated backup import into a new recoverable library, and only adopt after durable success. Never silently overwrite/quarantine-and-discard the original. Acceptance should cover cancellation, malformed backup, write failure, and preserved corrupt-file hash.

2. **P2 first-use create/import obstruction and missing actionable onboarding.** `KeyAndFillApp.swift` starts directly in Studio; `StudioPreferences.swift` has no first-run state. `StudioGuideView.swift` is a substantial existing help guide, so help is not absent, but its workflow is text-only. On a fresh install, `saved == nil`, and `ProjectLibraryView.swift:39–46,110–125` disables both New and Import until Save current setup creates a default project. Reproduction: fresh installation → Projects → observe disabled New/Import despite no saved projects. The product/design contract expects a quick guided three-light success. Add a dismissible first-use route with explicit starter/import actions; preserve a genuinely edited unsaved scene. Do not force an unwanted placeholder project solely to restore a backup. Acceptance: first use, skip/resume, returning-user noninterruption, failed import preserving the current scene, largest Dynamic Type.

3. **P2 beta feedback/support handoff absent.** Settings contains Workspace, Purchases, photograph/project explanations and About/version (`App/StudioSettingsView.swift:13–60`), but no report/feedback/help-contact action. No onboarding, feedback-recipient, or TestFlight feedback UI exists in App source. A beta tester cannot produce a structured issue including version and reproduction steps from the app. Add a local, user-reviewed shareable feedback draft with app/build version and opt-in reproduction notes. Exclude photos, scene names, coordinates, and device identifiers by default; do not invent a support email or transmit automatically. Existing editable backup/PDF exports can be attached separately by explicit user action.

No additional P0 or proven crash/payment/data-loss defect was established in this bounded audit.
