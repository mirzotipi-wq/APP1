## Findings and agreed design

Read worker reports 049/050 and their retained probe source/output, then inspected the actual `StudioSession`, `StudioPlanMarkers`, relevant `StudioView` bindings, `StudioEditorState`, `SceneEditHistory`, and existing Plan/session test contracts. The marker freezes its change/end closures at first recognition; `.onEnded` explicitly delivers the last cumulative translation before completion. Parent-only retirement therefore needs independent callback identity even when selection and storage generation remain unchanged.

051 proposes explicit `beginPlanDrag(lightID, scale, from:) -> UUID?`, a token stored in `PlanDrag`, strict token-qualified changes/ends, and a separate unqualified lifecycle finish. A value callback will never start a transaction. This design addresses the established same-generation replay defect without rotating unrelated document identity.

Sent these concrete requirements early; 051 confirmed the core contract:

1. Latch the **attempted begin** for the recognized local gesture even when begin returns nil. Subsequent samples from that touch must not retry when a busy/invalid condition clears. Local completion/cancellation resets that latch.
2. Freeze token plus original callbacks, generation and scale. A nil/rejected begin must never flow into unqualified completion and close another gesture.
3. A retired token must reject both delayed changes and delayed ends after a fresh gesture starts on the **same light and generation**. Use a distinct history owner per token.
4. Foreign `apply`/`update` must stage the Plan history boundary on an editor copy, publish/retire only after an accepted change, and preserve exact editor/drag/redo state for invalid or unchanged commands. Plan’s own mutation must bypass this foreign-command boundary.
5. Unqualified `endEditing`, and matching Plan-owner endings, must retire the token; an unrelated owner’s end must preserve the current gesture. Merely closing history while keeping an active Plan token permits later values to escape their intended undo group.
6. Build movement from live unaffected height while retaining frozen x/z origin and scale. Selection changes, accepted replacement, other-control begin, parent finish and existing-project save must retire the prior token.
