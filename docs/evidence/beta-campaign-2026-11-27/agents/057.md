## Findings

1. **Ordinary edits preserve orbit; Fit explicitly resets it.** SceneKit limits fitting to initial/mode presentation or a changed request (`SpatialPreview.swift:204–289`), keeps the actual `pointOfView` and controller target during edits, and stops inertia before Fit. Invalid scene recovery preserves pending mode changes. RealityKit keeps per-coordinator `SpatialOrbitState`, marks `needsFit` only for initial/request changes and consumes it after valid viewport layout (`RealityStudioPreview.swift:189–245`). Geometry and selection updates do not overwrite that state.

2. **Identity and stale references are guarded.** Both adapters reuse fixtures by UUID, remove deleted roots and reject retained deleted objects through live ownership/parent checks. Invalid input clears equipment identity maps. SceneKit shape changes preserve fixture/source/stand identity; RealityKit changes materials/transforms/components in place. Callbacks refresh even for equal scenes. The parent additionally checks project-operation generation and current UUID membership and scopes each surface to `workspaceResetID` (`StudioView.swift:432–464`). Stale selected UUIDs produce no active outline.

3. **Cancellation, teardown and isolation appear coherent.** UUID-set changes cancel active selection/gestures. SceneKit dismantling removes targets/delegates, stops inertia, clears scene/camera references and releases geometry. RealityKit disables interaction and detaches anchors outside active windows, clears closures/targets/anchors on dismantling, and constructs a non-AR view with automatic session configuration disabled (`RealityStudioPreview.swift:70–82,154–226`). Geometry caches, callback state, navigation and maps belong to each coordinator/graph; no shared mutable singleton appeared.

4. **Fallback claims remain bounded.** Intel simulator builds choose SceneKit before constructing RealityKit resources. Both surfaces label lighting illustrative; the RealityKit branch additionally discloses the first-seven-active-lights shading limit. The user-facing note does not name the renderer, but does not claim RealityKit or calibrated output. Architecture documentation names the fallback; native snapshot attachments explicitly include `SceneKit`.
