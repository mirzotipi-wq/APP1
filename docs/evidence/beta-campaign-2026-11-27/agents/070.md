## Finding: P2 target-lux draft lacks its locale owner

`App/LightTargetLuxView.swift:17–21,83–86,108–115` stores raw text but evaluates it using the **current** environment locale. It captures no draft locale and has no locale-change handler or Apply-time locale guard. Consequently, if SwiftUI updates the locale while this sheet remains mounted, existing text can acquire a different interpretation without another edit.

Concrete witness: an English `1,000` draft is rejected; changing only the locale to French makes the identical text an accepted **1 lx** target. Apply then computes and submits that target. This is a draft-context gap, not a parser arithmetic error. Feature receipts protect scene ownership but contain no input locale, so an otherwise unchanged scene does not reject the proposal. A private Foundation probe extracted the exact `target` property and pinned parser: three assertions passed, confirming rejected → accepted transition with unchanged raw text. Native locale-update reachability and SwiftUI presentation behavior were **not executed**.

**Recommendation:** capture the draft locale at initialization, invalidate/cancel or explicitly restore the draft when it changes, and check the captured locale before both target preview and Apply. Add a hosted-view regression that changes the environment with an unfinished target-lux draft. Do not mark this as a native reproduction.
