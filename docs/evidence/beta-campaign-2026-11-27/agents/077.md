History can report revoked/unverified but cannot grant access. Verified purchase/update results also require matching ID and type (`205–253`) and re-read current entitlements before finishing. Unverified results trigger a re-read and never directly grant or revoke access. `hasLifetimeAccess` depends only on `.purchased` (`43`), not an outcome message.
- **Expiry and product lookup:** `270–279` rejects a configured subscription or other non-lifetime product; the accepted entitlement type is also restricted to nonconsumable. No subscription-expiry authorization path exists. Product lookup state is separate from verified entitlement state (`168–181`), so a price lookup failure does not itself remove access. - **Ownership, cancellation and late work:** `App/KeyAndFillApp.swift:6–28` owns one store and refreshes on subsequent active transitions. `App/ProFeaturesView.swift:266–289` reserves an action before scheduling and calls the shared store; closing the sheet does not destroy it. The updates listener weakly references the store between events, checks cancellation and is cancelled in `deinit` (`EntitlementStore:65–88`). Product lookups check cancellation before publication. Relevant verified transactions use a separate finite handling task, intentionally allowing delivery reconciliation after caller cancellation (`231–248`); the transaction is finished only after current purchased/revoked state is established. In-flight duplicate finishing is guarded by transaction ID.
- **Outcomes and races:** busy guards serialize purchase/restore (`100–164`). Cancelled/error outcomes do not grant access. Pending disables another purchase; an empty refresh/restore deliberately does not infer that approval was declined (`184–201`). A revision change following observed ownership prevents an older `.pending` result reopening that approval (`108–128`). Entitlement reads detect an intervening refresh generation and retry (`184–201`). These mechanisms were inspected, not proven under real StoreKit scheduling.
- **Restore and features:** the sole `AppStore.sync()` call is explicit restore (`149`), reached through the Restore button; launch/resume uses refresh. Restore derives its final status from refreshed entitlement, with distinct pending/nothing/revoked/unverified/cancelled outcomes. Repository-wide caller search found entitlement checks only in purchase/status presentation: `StudioSettingsView:36–37`, `ProFeaturesView:19–20,75–110,162–175,245–246`. Current editing, projects, AR and export are not gated by this store.
