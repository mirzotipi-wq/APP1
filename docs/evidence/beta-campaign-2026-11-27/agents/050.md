## Finding

**Confirmed source-contract defect; native delivery/reachability remains unobserved.** `StudioSession.dragLight` (248–269) implicitly opens a new Plan transaction whenever `planDrag == nil`. Its only identity guards are the selected light and storage generation. A completed/cancelled gesture's cumulative sample is therefore indistinguishable from a new gesture.

The real adapter retains `dragChange` and `dragCompletion` from the first recognized sample (`StudioPlanMarkers` 208–218). Parent lifecycle handling (`StudioView` 240–245), successful same-ID replacement, another control beginning, and library reservation can clear the session's Plan state without synchronously clearing that marker's local `dragInProgress`. Marker `.onEnded` explicitly sends the final cumulative translation **before** `finishDrag` (220–222). The scene-phase handler does not disable Plan input, and generation does not change for an ordinary existing-project save. If a final sample follows one of those parent boundaries, the origin rebases to the already moved scene and the displacement is added twice.

The marker's own cancellation path clears its stored callbacks before completion (226–234); an end delivered after that local cleanup does not write. Selection change also removes the old marker's drag callback, and project-generation change rejects old updates. These defenses narrow the exposure but do not cover parent-only completion with the same selected ID/generation. SwiftUI cancellation/render scheduling and simultaneous-control delivery were not exercised on an Apple runtime, simulator, or physical device.

## Recommendation

Authorize a narrow fix in existing Plan/session files: explicit gesture begin returns a token; the marker retains it for that recognized gesture; changes and qualified ends require the currently active token. Clearing Plan retires it. A value callback must never implicitly recreate a retired transaction. Merely adding a token to the current auto-start path is insufficient; rotating document generation would unnecessarily invalidate other drafts.

Regressions should cover parent finish/replacement/control/save followed by stale change, and an old end after a new same-light gesture. Preserve invalid/no-op behavior and cumulative origin/scale invariants. Separately preserve live y, or retire Plan on accepted foreign commands, with an explicit undo-boundary test. Recommend repair as a concrete editor robustness issue without claiming a reproduced physical interaction or assigning release-blocking severity from unobserved native timing.
