# W004 — Reject malformed numbers in ignored project metadata

**Result:** Fixed a demonstrated JSON validation gap at baseline `804c2c7ae21cdc9a4f7da9c68ea19b0cd3c7db42`. No commit or push performed. Worktree: `/tmp/app1-worktrees-0eff52f/w002`.

## Defect and change

Foundation deferred numeric conversion for unknown scene metadata, accepting malformed JSON number tokens such as `1e`, `1e+`, `1e-`, `--1`, `-`, `01`, and `1.`. The existing external-document scanner validated strings and duplicate keys but did not validate number grammar. A probe against the actual baseline LightingCore module confirmed acceptance on Swift 6.2; this was not only a model/stub result.

`LightingProjectDocument` now scans number tokens with bounded, linear byte processing: optional minus, valid integer portion, required fraction digits, optional signed exponent with required digits, and legal terminators. It does not convert ignored values or impose a Double magnitude limit. Valid unknown metadata, UTF-16/32 variants, number-like strings and existing legacy scene behavior remain supported.

Five new regression methods challenge malformed tokens at four nesting positions, valid numeric grammar and large magnitudes, numeric-looking string/key contents, supported Unicode encodings, and invalid suffixes/literals.
