**Result:** No demonstrated production defect; no source change. Reviewed base `804c2c7ae21cdc9a4f7da9c68ea19b0cd3c7db42` plus root's pending changes. The five bound files were unchanged in the working diff. Actual context: `/root/beta_campaign/w012_bounded_file_boundary`.

## Invariants challenged

- Metadata preflight is advisory. Missing/inaccessible metadata proceeds to coordination; passing preflight does not authorize a later path. The actual open requests no-follow/nonblocking/close-on-exec flags, then checks the opened descriptor's regular-file type and size. A later pathname replacement cannot redirect that descriptor.
- `maximumBytes` rejects negatives and `Int.max`. At each loop entry, the accumulated count is at most the permitted maximum, so `maximumBytes + 1 - count` is positive and cannot overflow. Reads request at most 64 KiB and consume at most one byte beyond the maximum before throwing. Exact-limit input gets a final one-byte EOF check; a file growing after `fstat` cannot escape the byte limit.
- Zero-byte limits accept an empty file; preexisting content is rejected by size, and content added after `fstat` is rejected after the first extra byte. Truncation can produce earlier EOF, but imports still pass their format/schema decoder before publication. The reader does not promise a coherent snapshot of an external writer's in-place changes.
- The `FileHandle` owns the descriptor immediately after successful open. Every subsequent exit, including type/size failure, cancellation and read failure, reaches deferred close. The reader never writes the selected file.
- Checkpoints enforce both real task cancellation and caller cancellation before reads and before return. Project import also checks after coordination and decoding, holds security scope through the accessor, and cancels the installed coordinator. Photo import uses the provider's temporary file within its transfer callback. Production callers supply fixed 8 MiB and 32 MiB limits; the generic reader is not a separate process-memory quota.

## Existing coverage and remaining boundary

The **13 reader test methods** cover metadata preflight, zero/exact limits, invalid limits, symlink/FIFO rejection, replacements before/after open, growth, and injected/actual-task cancellation. These are an inventory, **not fresh native passes**.

Cancellation is cooperative between synchronous filesystem operations. Source inspection establishes no wall-clock deadline for a slow provider operation already in progress. Real provider materialization/cancellation and descriptor behavior still require Apple/provider execution; a Linux adaptation would not establish that result.
