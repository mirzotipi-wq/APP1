## Independent falsification

Linked a separate executable to the actual patched LightingCore build, using Swift 6.2 on Linux. Its independently generated corpus compared public document decoding against an ASCII JSON-number grammar oracle: **72,766 cases, 7,981 accepted, zero disagreements**. The corpus exhausts length-one-through-five strings over `-+.eE0129`, then adds seeded valid/mutated forms, nested object/array and whitespace placement, numeric-looking strings, Unicode digit/sign challenges, and UTF-8/16BE/16LE/32BE/32LE encodings.

The first oracle incorrectly treated legal edge JSON whitespace as part of a number token, producing 120 false discrepancies. Both the initial generator and results are retained. Correcting only the oracle to remove the four legal JSON whitespace characters at token edges resolved every discrepancy; no app code was changed to satisfy the probe.

The actual decoder accepted a valid **8,388,608-byte** document with one large ignored integer and rejected **8,388,609 bytes** as `tooLarge`. Arrays of 1,024, 16,384 and 65,536 numbers all decoded. The final Debug host observations were 0.340 seconds for the limit-sized integer and 0.051 seconds for the 65,536-number array. These are bounded workload observations, not device performance acceptance or calibrated benchmarks.

Source review confirms monotonic byte-index advancement, required digits after a fraction/exponent marker, valid delimiters, and no numeric magnitude conversion. The delimiter is revisited by the structural scanner, preserving object-key scope. The patch leaves stored-library/SceneCodec behavior unchanged.
