## Findings

- `SpatialPreview.orient(_:to:negativeZForward:)` uses `(right, up, normal)` for fixtures and `(-right, up, -normal)` for lights. `StudioLampEntity.update(light:subject:selected:shades:)` uses the same fixture basis; its emission child rotates π around local Y. These are mathematically equivalent proper rotations: native −Z maps to the shared emitting normal. `EmitterFrame.init(source:target:rollDegrees:)` applies positive roll right-toward-up once; neither adapter reapplies roll. Vertical aims retain its deterministic basis.
- Rectangle housing width/height match authored meters in both adapters. SceneKit offsets its box by half-depth behind the authored plane; RealityKit places its diffuser front at local z=0. Point optics select spheres and omnidirectional lights; coincident aimed targets suppress light emission. SceneKit registers fixture/stand identities and resolves ancestors; `StudioEntityGraph.lightID(for:)` resolves persistent UUID roots through ancestors.
- **Concrete display discrepancy, not a proven physical-model defect:** for valid rectangle width=height=0.05 m, `SpatialPreview.populate(_:coordinator:)` constructs a 0.05×0.05 box. `StudioLampEntity.update` keeps that housing size but sets `face.scale` to 0.038×0.038×0.006: each visible diffuser dimension is 24% smaller. For the existing 1.2×0.7 fixture, the RealityKit diffuser is 1.188×0.688. These illustrative adapters also intentionally differ in housing depth/point radius.
