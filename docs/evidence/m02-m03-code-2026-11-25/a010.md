# a010 — paired finite-emitter culling benchmark

**Worker:** a010 of 100. **Date:** 2026-11-25. **Scope:** targeted retention diagnostic; production source read-only. No commits, pushes, full benchmark rerun, or repeated broad correctness campaign.

## Recommendation

**Retain the guarded back-side culling optimization.** The away-facing finite-emitter workloads consistently benefit, with identical complete image bytes, validity masks and exact receiver-value bit patterns. Ordinary-facing results are noisy and do not establish a reliable improvement or regression. This recommendation rests on avoiding zero-contribution work in the away-facing case, not a general rendering-speed claim. Existing baseline/candidate full benchmarks remain separate evidence; their ordinary-facing results also do not establish a clear speedup.

## Method and environment

Host: **Linux-6.18.57-x86_64-with-glibc2.41**, **AMD EPYC 9V74 80-Core Processor**; Swift **6.2.1**, `x86_64-unknown-linux-gnu`. Each executable was pinned to logical CPU **0**, one of **9** allowed CPUs. The CPU was not reserved and shared-host contention was uncontrolled. Compiler processes finished before timing. Baseline/candidate compilations exited 0 in 33.072/32.493 seconds respectively. Raw measurements completed at **2026-11-25T18:11:27.899601+00:00**.

The ordinary scene matches `scripts/benchmark-study.swift` area3: portrait lights, camera `(0, 1.60, 1.7)` meters, 85 mm lens, 5600 K white balance, +1.25 stops, rectangle sizes `1×1.2`, `0.8×0.8`, `0.4×0.8` meters, 8×8 samples per emitter (192 per receiver). Away-facing changes only each aim target to `2 × light.position − subject`, reversing the emitting direction. Both scenes render sphere and bust at **144×96**.

Each invocation performs one untimed warm-up and one measured render using `DispatchTime` monotonic wall time. It asserts repeated full `StudyImage` equality and zero unsupported pixels. Timing excludes file writing, hashing, receiver-value probes and process startup. The renderer includes its usual scene setup and image production. Each invocation also evaluates the same 32 receiver positions, saving the five Double bit patterns (visible lux, unoccluded lux, XYZ) per receiver.

Ten pairs per workload/version yielded 80 measured renders and 80 warm-ups. Odd pairs run baseline then candidate; even pairs reverse that order. Odd-pair workload order is ordinary sphere → ordinary bust → away sphere → away bust; even pairs reverse the workload order. Each pair remains adjacent within its workload.

## Limits and process finding

This is a short Linux CPU diagnostic for the selected facing configurations. It neither proves physical-device performance nor supplies GPU, thermal, memory, sustained frame-rate or calibrated-photo evidence. The all-away case is deliberately favorable to the shortcut; frequency in real editing sessions is unknown. Existing broad correctness and complete benchmark evidence are not replaced. The robust retention argument is the consistent elimination of otherwise useless work, with exact outputs and no demonstrated ordinary-path regression in these noisy samples.

Process finding: collect optional host metadata before expensive measurements, or tolerate missing metadata paths. The failure here occurred only after data had been flushed, enabling exact recovery without repeating the benchmark.
