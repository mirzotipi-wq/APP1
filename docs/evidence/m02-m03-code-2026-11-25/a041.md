## Finding

**P2: one room presentation can become multiple Undo transactions after inactivity.** `StudioView.swift:264–265` ends every active edit when scenePhase leaves active. `applyRoom`/`removeRoom` subsequently begin another transaction with the same presentation owner (`1151–1178`), while the room sheet remains open. Source-derived sequence: open room; Set width; background/foreground; Set depth (or remove room); Done; Undo restores the first edit, not the setup before the room editing session. This contradicts the removal confirmation/help promise in `ManualRoomPlacementView.swift:116,167`. No edits are inherently lost; the advertised single-session rollback is split. Suggested regression: multiple room changes separated by inactive/active, then one Undo/Redo and exact scene comparisons. Decide whether to preserve the room transaction through inactivity or explicitly define/document the boundary.
