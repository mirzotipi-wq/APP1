## Findings

No concrete critical defect found in the reviewed integration.

- **Types/isolation:** `StudyFrameCache` requires `Key: Equatable & Sendable` and `Value: Sendable`; `CacheKey`, `LightingScene`, `StudySubject`, `StudyRenderedFrame`, and `StudyImage` satisfy the declared requirements. Cache mutation remains actor-isolated and synchronous. This is source analysis, not an Apple Swift 6 typecheck.
- **Identity/validation:** exact scene equality preserves all rendering inputs, light IDs/order, optics, lens, exposure, room metadata, subject choice, and effective width. Only validated display names are removed. Invalid metadata cannot hit a valid entry. Bust requests share the existing 144-pixel clamp; sphere width remains distinct. Invalid keys proceed through the original renderer, preserving resolution/camera/scene error ordering.
- **Bounds:** the actor passes four entries, 262,144 RGBA bytes, and 65,536 mask bytes. Admission charges actual `Data.count` for both payloads. Oversized/negative costs reject before mutation; replacement removes its previous charge; eviction precedes append; subtraction comparisons avoid integer overflow. These are retained payload limits, not process-memory measurements.
- **Cancellation/failure:** task cancellation is ORed with the additional predicate. Checks precede lookup promotion and every successful admission; there is no suspension between the final check and admission/return. Throwing render paths never retain their output. Successful CPU fallback may be cached. Cancellation during initial parity leaves the backend unchecked for retry.
- **Downgrade:** `selectCPU()` removes all Metal entries while preserving CPU entries and survivor recency. Per-scene precision routing does not downgrade the backend.
