# Worker a007 — portable bounded Study frame cache

## Scope and implementation

Worker 007 of 100, M02 under `m02-m03-code-v2`, 2026-11-25. Base HEAD was
`48c287c54ccaaa71fca4170615e7491551798aaa`, with other workers' existing changes
preserved. This worker owns only `Sources/LightingCore/StudyFrameCache.swift`,
`Tests/LightingCoreTests/StudyFrameCacheTests.swift`, and this report. No app
renderer, shared state, acceptance contract, or existing test was changed.

The new public `StudyFrameCache<Key: Equatable & Sendable, Value: Sendable>`
makes LRU storage and both payload budgets executable without an Apple SDK.
Its immutable positive limits are configured with
`init(maximumCount:maximumPixelBytes:maximumMaskBytes:)`; observable `count`,
`pixelBytes`, and `maskBytes` expose retained accounting. `value(for:)` promotes
a hit. `insert(_:for:pixelBytes:maskBytes:)` returns admission success, rejects
negative or individually oversized costs without mutation, replaces a matching
key before eviction, and evicts oldest entries before appending. Separate
remaining-budget subtraction checks prevent arithmetic overflow. Zero-cost
entries remain subject to the count limit. `removeAll(where:)` accepts a value
predicate and preserves survivors' relative recency while subtracting both costs.

Twelve behavioral tests cover empty/configured bounds, 100 zero-cost admissions,
hit/miss recency, independent pixel and mask pressure with multiple evictions,
the actual 4-frame/256-KiB/64-KiB accounting configuration across 100 mixed-size
admissions, same-key replacement and changed costs, rejection without replacement
or recency changes, `Int.min`/`Int.max` admission and accumulation boundaries,
backend-selective invalidation/reset/reuse, and equality without Hashable keys.

## Integration and limits

App integration is separately assigned. The owner remains responsible for
accurate payload costs, bounded key/value metadata, synchronization, and
cancellation checks before cache lookup/admission. Because lookup immediately
promotes recency, the actor should check cancellation before calling it. Native
rendering, cache identity, cancellation, and backend-fallback checks must still
run against the integrated actor. This packet establishes portable storage
behavior; it does not establish actor integration, actual Metal execution,
physical memory/performance, or completion of M02/M03.

Self-review checked admission before mutation, replacement accounting before
eviction, both independent subtraction guards, and survivor ordering after
reverse-index removal. The concrete process improvement is executable portable
coverage of mask pressure and extreme integer costs, previously inaccessible
through the Apple-only actor tests. No commit, push, or child worker was created.
