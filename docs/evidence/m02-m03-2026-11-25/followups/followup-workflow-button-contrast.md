# Focused contrast review: two workflow buttons

**Result: no concrete current text-contrast defect in either inspected button. No patch proposed.** Both rendered color pairs measure **4.768334395441173:1**, above the stricter 4.5:1 normal-text benchmark. This does not claim an accessibility-audit pass or identify the two historical contrast findings whose elements were unknown.

## Typography and measurement limits

Neither label nor its ancestors specifies `.font`, `.fontWeight`, `.bold` or a control-size override. The native default rendering is regular, body-sized text. Its observed line advance is 66 image pixels / 3 = 22 logical points, consistent with Apple's default **17-point regular Body / 22-point leading**. This font identification is a source-and-rendering inference: the retained AX hierarchy does not expose a resolved UIFont descriptor or content-size category. It is therefore classified conservatively as **normal text**, with no large/bold exception used. See [Apple typography specifications](https://developer.apple.com/design/human-interface-guidelines/typography).

Four text-only interior bands contain 2,956 exact foreground pixels for Reference and 2,931 for Room, including hundreds of solid 3×3 glyph neighborhoods in each label. Background samples above, between and below the text agree. Coordinates, counts and samples are retained in the linked measurement receipt. Anti-aliased edge pixels were not mistaken for the intended foreground color; [W3C's contrast guidance](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) calls for evaluating underlying/resolved colors, and sets 4.5:1 for ordinary text.

This conclusion covers these two enabled labels in this retained light-mode state. It does not resolve dark mode, other controls or states, Dynamic Type behavior, unknown historical issue identities, the incomplete Intel audits, or the required manual device accessibility gate.
