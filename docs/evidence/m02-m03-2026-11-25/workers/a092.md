## Wrapper behavior

`scripts/run_atomic_library_write_probe.py --output NEW_DIRECTORY [--swiftc COMPILER]` requires a fresh output directory with an existing parent. Existing evidence is never overwritten.

The wrapper records the checked-out Git base revision, host/Python information, exact invoked `swiftc` path, resolved target, complete `--version` output, compilation argument array, and source hashes. It deliberately retains the `swiftc` invocation name when it is a symlink, since invoking a resolved Swift driver under a different name can alter driver mode. The macOS workflow explicitly supplies the active compiler from `xcrun --find swiftc`.

Compilation is an independent child process using `-O` and a private temporary module cache/output executable. The manifest hashes every compiled Swift input before and after compilation; it re-enumerates the core directory so additions and removals also invalidate provenance. It separately hashes both Python diagnostic scripts. A changed input or diagnostic, compiler failure, or compiler timeout prevents probe execution. The executable's SHA256 is recorded under the exact helper filename expected by a089's manifest validation.

The existing runner receives the actual helper, the manifest, a new `probe/` output subdirectory, and the base-revision label. The wrapper additionally checks source/diagnostic hashes after the probe and requires the runner to exit successfully with a passing result file. The base revision is labeled separately from the working-tree hashes; uncommitted compiled inputs are not represented as an exact clean HEAD build.

The wrapper never sets resource limits or signal dispositions. a089's unchanged runner continues to apply `RLIMIT_FSIZE` and ignored `SIGXFSZ` only to the injection child. Compilation and unrestricted setup/control remain outside that injected bound.

Bounds:

| Operation | Limit |
|---|---:|
| Source revision metadata command | 10 seconds |
| Compiler version command | 10 seconds |
| Helper compilation | 180 seconds |
| Existing probe runner | 140 seconds |
| Each added CI probe step | 6 minutes |

The existing runner still bounds each of its four helper phases to 30 seconds. The wrapper's runner deadline includes margin above their combined 120 seconds. Existing core 20-minute and simulator 90-minute job deadlines and every pre-existing step deadline remain unchanged.

## Evidence retained by CI

Both jobs tee the entire wrapper/runner CLI output to a runner-temporary log and immediately run a dedicated `if: always()` upload step:

- `atomic-library-write-linux-evidence`
- `atomic-library-write-macos-evidence`

The dedicated artifacts retain the CLI log and the complete evidence directory: compiler version/revision logs; compiler stdout/stderr; `compile-manifest.json`; `wrapper-result.json`; probe stdout/stderr; all original phase observations/error logs; exact prior/candidate/after/control snapshots; final checks; and the runner's copied compile manifest. Compiler output and the raw probe JSON are also forwarded into the step log. Temporary build binaries/module caches are removed after the attempt; the exact binary hash and compiler invocation remain in the manifest.

Separate artifact names avoid changing the common ancestor or internal paths of any existing test artifact. Upload occurs immediately after the probe attempt, before longer subsequent build/test phases.
