# A077 — Studio project transitions

No concrete defect found in read-only review.

Dirty scenes block create, select, duplicate, and archive twice: `ProjectLibraryView.canMutate` and `StudioView.applyLibrary` (1266–1268). They require an explicit save; conflict reload separately requires the “Reload and discard edits” confirmation (279–283).

Create/duplicate/select change active identity, rotate the editor generation, reset history, dismiss scene editors, and select the destination’s first light (`ProjectLibraryOperation.swift` 121–134; `StudioView.swift` 1298–1306). Inactive archive preserves current selection/history; active archive is prohibited.

Duplicated light UUIDs cannot authorize old writes: bindings capture the generation, control owners additionally include project identity, and native slider sessions retain their original adapter. Delayed ends are owner-qualified; retired tracking tokens cannot reopen history (`StudioView.swift` 865–979; `StudioSliderTracking.swift`).

Existing transition tests were inspected, not executed. No source edits or builds.
