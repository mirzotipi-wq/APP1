## Observations and diagnosis

The domain assertions had already succeeded before the failure. The hierarchy contains `roomPlacementStatus` with `All 5 center positions inside room`, `modifierCrossingStatus` with `1 rectangular modifier crosses a wall`, `roomSubjectX` with value `1.6`, and `emitterWidthExact` and `emitterWidth` with value `1.237 m`. The failure is navigation to the status, after the real edit and semantic checks.

The hierarchy gives the app frame as 402 × 874 points. The room sheet's navigation bar occupies y=78 through y=132. The final crossing-status frame is x=31.7, y=-305.3, width=303.0, height=20.3. The shared reveal helper uses the app viewport inset by 100 points, so it admits centers starting at y=100; it separately requires the target to be hittable.

The log records exactly twelve reveal gestures, alternating on every iteration:

1. Drag from normalized y=0.30 to y=0.78, toward the summary above.
2. Drag from normalized y=0.78 to y=0.30, away from that summary.

This two-gesture sequence repeats six times. After each first gesture, the log includes the additional target lookup consistent with the helper evaluating hittability for a center inside its generic viewport; it then reverses because the call's default `towardBottom` is true. After each reverse gesture, the helper immediately returns to an upward gesture.

Inference from these observed coordinates, source branches and event sequence: a 419.52-point upward-content reveal moves the status center from roughly -295 to roughly 124, within the helper's y>=100 viewport while still beneath the room sheet's navigation bar ending at y=132. The target therefore remains unhittable; the unspecified fallback direction reverses navigation instead of continuing toward the summary. Intermediate target frames were not logged, so the approximately 124-point center is a geometric inference rather than a directly captured frame. The repeated reversals themselves are directly recorded.

## Correction and preserved contract

Passing `towardBottom: false` supplies that intended direction when the frame is inside the generic viewport but actual hittability is still false. The existing helper retains its position-based override for genuinely offscreen targets, its twelve-gesture maximum, and its requirement for a finite, nonempty frame whose center is in the viewport and whose element is hittable. It still fails with genuine screenshot/hierarchy diagnostics if the status cannot be reached.
