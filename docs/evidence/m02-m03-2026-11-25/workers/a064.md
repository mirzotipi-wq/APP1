## Implementation

Added `SceneTransform.arranged(_:subjectAt:rotatingLightsByDegrees:mirroringLights:)`.
It rejects nonfinite transform parameters, validates and migrates the source,
rotates lights and explicit aims around the original subject, optionally mirrors
them across the original camera center plane, and translates the complete setup
to the chosen subject position. Only the input and completed candidate undergo
scene validation; a temporary out-of-range rotation or reflection is allowed.
The entered subject destination is retained exactly.

Existing public single-operation APIs keep their input/output validation and
error behavior. Their geometry was extracted into private composition helpers;
exact cardinal rotation coefficients and the existing exact axis/diagonal mirror
formulas were retained. Room measurements, camera lens, preview settings, source
identities, ordering and photometric properties continue to travel unchanged.

A necessary companion fix handles overhead rectangular emitters. Their roll
reconstruction formerly depended on bounded world-space frames. Temporary
out-of-range lights/aims now use a privately rebased direction to construct the
same shared `EmitterFrame` basis. This preserves rectangle orientation during
composition without changing `StudioOptics.swift` or relaxing public validation.

The arrangement sheet calls the combined API once. Existing completion latching,
single `onApply` invocation, parent stale-result checks, selection by preserved
IDs, and one replacement/history transaction remain in place.

## Added portable regressions (10 test methods)

- Both signed versions of the original case: subject x = ±99, light x = ±90,
  yaw = 180°, final subject x = 0, resulting light x = ±9. Standalone rotation
  still rejects the invalid intermediate x = ±108.
- Reverse-order counterexample: subject x = 0, light x = ±9, destination x =
  ±99, yaw = 180°. Translating first fails, while the completed light is ±90.
- Mirroring rescues an out-of-range intermediate rotation without translation.
- Rotation-before-mirror order, translated camera and camera direction, manual
  and subject-following aims, exact metadata, lens, room, optional optics and IDs.
- Actual invalid completed light (104 m after rotation plus translation), camera,
  explicit aim and subject coordinates reject atomically without assignment.
- Invalid source geometry/schema cannot be repaired through a transform.
- Nonfinite angle/destination rejection and unchanged undefined camera-plane
  behavior when mirroring.
- Exact quarter-turn and diagonal-mirror boundary positions and explicit aims.
- A non-square, rolled, downward-facing rectangle retains its actual four
  corners after a 90° rotation whose intermediate light and aim have x = 108,
  both with and without mirroring.

## Recurrence prevention

The escaped defect came from composing separately validatable operations for a
single UI transaction. The regression tests exercise final-state validity in both
ordering directions and physical emitter corners, preventing a mere order swap
or validation bypass from appearing to fix the composition contract.
