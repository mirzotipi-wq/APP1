## Exact behavior

`StudyImage` retains `unsupportedPixelMask`, a row-major `Data` value with one byte per pixel: 0 valid, 1 unsupported. Both CPU renderers set this byte in the existing invalid-surface catch without changing sampling. `fromComputeRGBA` retains the existing alpha-0 flag before restoring display alpha to 255. An opaque magenta pixel remains valid unless explicitly flagged.

The prior internal initializer argument labels remain available. Its added mask argument defaults to empty metadata, not an inferred mask. Even a zero-unsupported image with an absent mask fails parity; a positive count never manufactures pixel locations. All three production constructors now supply the explicit mask. No NativeTests constructor edits were needed.

`StudyParityMetrics.init` returns nil for any of:

- Nonpositive dimensions, differing dimensions, overflow in `width * height` or in `pixelCount * 4`, or either buffer not exactly that byte count.
- Missing, short, or long masks; mask bytes outside 0/1; negative or excessive unsupported counts; or a mask population inconsistent with its image's count.
- Nonopaque display RGBA alpha, consistent with the existing StudyImage display contract.

Well-formed images still produce metrics when masks differ. The existing `invalidCountMatches` diagnostic is preserved; new `invalidMaskMatches` reports exact mask equality and is additionally required by `passes`. RGB gates remain mean <= 1 and fraction of channel errors > 4 <= 0.005. Maximum channel error remains diagnostic in Swift. Error accumulation uses Double to avoid integer-sum overflow; all supported study image sums remain exactly representable.

Both fixture producers encode the retained mask into fixture alpha (0 unsupported, 255 valid), while display `rgba` stays opaque. The C++ verifier validates reference alpha, flagged magenta, header unsupported count, exact buffer length, and each candidate/reference invalid location. Header width/height bounds precede size products and allocations. Default and strict numerical limits are unchanged, including `--maximum-channel-error`. Output adds `invalid-mask-mismatches`.

## New portable regressions

Nine XCTest methods cover:

1. Identical valid images and identical images with an explicit unsupported pixel both pass; display alpha remains opaque.
2. Moving one invalid pixel onto a black valid pixel in a 48 x 32 frame fails, despite unchanged count, mean 1020/4608, and outlier fraction 4/4608 satisfying the old gates.
3. Swapping invalid flags between two magenta pixels fails even when the entire display RGBA buffers are equal and RGB error is zero.
4. One isolated 255-channel error still passes under the existing aggregate RGB limits, protecting the diagnostic-only maximum behavior.
5. Equally truncated buffers (whole pixel and partial pixel), equally extended buffers, and empty buffers fail.
6. Nonpositive, overflow-producing, and mismatched row dimensions fail without large allocations.
7. Missing masks (including positive counts), malformed bytes/lengths, and inconsistent counts fail closed.
8. Nonopaque display RGBA is rejected.
9. Both CPU renderers retain masks for established near-field fixtures, with mask populations matching counts and self-parity passing.

- Run `swift test --filter StudyParityMetricsTests`, then the required integrated suites. Regenerate both host fixture sets before running `verify-kernel-host`; the existing CI steps already regenerate them.
- Historical binary fixtures with positive unsupported counts and all-opaque alpha now fail closed with `reference invalid count does not match header`. Do not reuse them as valid current fixtures or infer flags from RGB. The fixture file length and header structure are otherwise unchanged.
- Suggested independent host adversarial check: after a regenerated near-field fixture passes, swap one invalid RGBA pixel with a valid pixel in the reference payload, preserving counts and header; the verifier must reject the moved mask even when the aggregate RGB gates remain satisfied. Truncating its RGBA payload must be a malformed-input error.
- Added retained mask storage is one byte per pixel: at most 24 KiB per current 192 x 128 image. The existing cache's 256 KiB cap counts RGBA only, so masks add at most 64 KiB of retained payload above that cap, plus ordinary collection metadata. Cache policy was not changed. Allocation/performance impact has not been benchmarked.
- StudyImage equality now also compares its explicit mask. Rendering remains deterministic, but pixels that display identically while differing in validity are intentionally distinct.
- A genuine Float32/Double invalid-location disagreement that previously slipped through aggregate counts will now reject parity and can select CPU fallback. This is the required semantic tightening; root must rerun host and actual Metal parity and retain any failure as evidence, without relaxing tolerances or changing sampling in this packet.
