## Changes

### Save and editing bar

`saveProject` now appears once in the persistent editing bar below the clipped scroll view. The label uses semantic body text, intrinsic vertical size, and a 44-point minimum target. At accessibility sizes, Save occupies its own row below the history controls; otherwise they share a row. The bar has no fixed height and is outside the scroll content, keeping Save reachable after scrolling to an inspector.

Save is unconditional within the bar. It remains visible with the exact existing disabled expression, `!loaded || saveBlocked || libraryOperation.isBusy`, during loading and protected/corrupt-library states. This preserves the `testCorruptProjectBlocksSavingAcrossRelaunch` contract. Its action still captures the presentation's `libraryOperation.generation` and calls the same `save(from:)` implementation.

History controls retain their loaded/not-blocked visibility condition. Both disabled expressions still include `libraryOperation.isBusy`, unavailable history, `editHistory.isEditing`, and `planDrag != nil`. Both operation methods retain their corresponding busy/editing/drag guards. The 44-point Undo and Redo controls and their identifiers are unchanged.

### Exact editor heading and Cancel

The first ordinary Form content row now contains visible `Exact value` and `precisionCancel`. At accessibility sizes the row stacks its heading and action; at regular sizes it arranges them horizontally. Both labels have intrinsic vertical size. Cancel has a 44-point minimum target and calls the existing `cancel()` function. The ordinary content position puts it near the top of the editor, including when the keyboard is shown.

`Exact value` uses semantic `.headline`, `.primary`, an explicit opaque `secondarySystemGroupedBackground` row backing, and the header accessibility trait. The failed native Section-header rendering has been removed. The navigation title, field, units, Apply action, error and range explanations remain. The live underlying-value, displayed-value, locale, range, active-presentation, and untouched-draft guards remain intact.

### Grid title and physical diagram

The same grid title is now a naturally sizing row immediately above the graphical canvas. Its semantic monospaced caption font can wrap; its height is not fixed. The enclosing preview stack includes both the title's natural height and the **unchanged 280-point canvas**.

The existing `GeometryReader` still computes the fit from the actual canvas width and height. `point`, `planMarkers`, the world fit inputs, and the complete `StudioPlanMarkerControl` implementation are unchanged. The real grid-spacing title travels through a small preference and updates state only when its string changes. The title cannot take space away from the diagram or cover its equipment. The title adds ordinary outer layout height; equipment retains its coordinates relative to its grid.

Caption placement now reserves the solver's normal 8-point margin because the title is outside the diagram. Selection priority and the collision solver itself are unchanged.

### Caption measurement and wrapping

Captions resolve `UIFont.preferredFont(forTextStyle: .caption2, compatibleWith:)` using the view's current Dynamic Type and legibility traits. The explicit mapping covers the seven regular and five accessibility categories, with `.large` as the unknown-category fallback. The convenience `UIContentSizeCategory(dynamicTypeSize)` initializer is not used.

The preferred descriptor retains the semantic text style and gains the requested weight. The same resulting `UIFont` is supplied to SwiftUI through `Font(font)` and to NSString measurement. No separate scaled point-size path or second font-weight modifier remains. The preferred font's point size is not capped. The caption width budget scales with that point size and the available canvas width.

The rendered Text has unlimited lines, a width constraint, and intrinsic height. Multiline measurement uses the same width/font and rounds up the larger of `font.lineHeight` and the measured bounds to a display pixel for collision placement. The collision rectangle never imposes an exact Text height. Short names retain their complete text; long names may wrap. A full caption that cannot be placed activates the existing visible `planLabelNotice`, with the selectable light list still available below. Visible captions remain accessibility elements. Bounded display-name input, leader lines, all marker actions, gestures, and stable IDs are preserved.

## Primary Apple references

- [Preferred UIFont with explicit traits](https://developer.apple.com/documentation/uikit/uifont/preferredfont(fortextstyle:compatiblewith:).md), available from iOS 10. Apple documents that font metrics can vary with language and device settings, that fonts are replaced when their content-size category changes, and that text should not be clipped to its line-height bounds.
- [SwiftUI Font from a platform font](https://developer.apple.com/documentation/swiftui/font/init(_:).md), available from iOS 13. Apple documents the UIFont/CTFont bridge used by `Font(font)`.
- [DynamicTypeSize](https://developer.apple.com/documentation/swiftui/dynamictypesize.md), available from iOS 15. Apple documents reading the environment and adapting horizontal/vertical layout for accessibility sizes.
- [UIContentSizeCategory](https://developer.apple.com/documentation/uikit/uicontentsizecategory.md) establishes the UIKit category names used in the explicit mapping.

These establish API/design direction, not a passing audit or pixel-perfect UIKit/SwiftUI layout result.
