# a022 — Decimal parser review

No blocking defect established by source/test inspection. Unicode input requires single-scalar decimal digits; superscripts, grouping, exponent syntax, misplaced signs, nonfinite results, and values outside the finite Double range are rejected. ASCII minus, Unicode minus, plus, and negative zero are handled. `editableText` verifies bit-for-bit reparsing; the editor also preserves untouched drafts and equivalent zero spellings.

Known limitation: raw Arabic/Persian negative readouts containing bidi marks cannot be pasted directly into `parse`; existing localized-readout tests explicitly remove those marks. Editor drafts intentionally use ASCII signs/digits, so ordinary unchanged editing avoids that path. No tests/builds executed; no native-behavior claim.
