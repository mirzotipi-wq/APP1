# Worker 23 — slider begin reentrancy

Implemented a narrow source-level ownership fix in the two assigned files. Ready for central validation; no further edits planned.

## Finding

`StudioSliderTracking.begin(B)` formerly ended A before allocating B's token. If A's synchronous end callback began C, the outer call then installed B over C without sending C its end callback. The added deterministic XCTest constructs exactly that ordering. This is a state-machine defect; current user-visible reachability is **not established**. Production `StudioView.editChanged(false)` calls owner-qualified `SceneEditHistory.end`, which does not itself begin another native touch.

## Change

- Reserve B's unique token before invoking external callbacks. If a newer begin changes the sequence during A's end callback or the binding read, return B's already-retired token without installing B.
- Returning a retired token preserves the existing caller contract used for reentrant invalidation at begin. It also ensures cleanup qualified by B's token cannot finish C; returning nil would expose the native wrapper's `currentToken` fallback.
- Normal begin, final-display publication, owner end, frozen adapter/mapping, cancellation, and stale-token handling retain their existing order and behavior. No UIKit source, timers, retries, or test weakening.

`testReentrantBeginFromPreviousEndKeepsNewOwnerAndRetiresInterruptedToken` asserts A closes once and remains undoable, B never begins or writes, C retains ownership, stale A/B samples and finishes cannot close C, and C's final sample commits once and undoes to its initial scene. A single `afterEnd` hook was added to the existing test helper.
