# Worker 28 — bounded comparative CPU diagnostic for grazing sampling

## Finding

The frozen candidate shows a material area-workload slowdown in this single paired run: median frame time increased **17.56–35.10%** across all four existing area-light render workloads. Each candidate area-frame sample was slower than every corresponding baseline sample. The receiver microbenchmarks increased **11.14%** without visibility and **10.66%** with visibility. This is evidence of a measurable candidate cost in the existing ordinary portrait fixtures; source bounds alone do not establish acceptable execution time.

The four point-light frame medians did not increase and their output hashes match exactly. All 12 cancellation probes per variant observed cancellation and returned; the largest deadline-to-return overshoot increased from **1.894443 ms** to **3.455934 ms**. No formal performance acceptance threshold was supplied, so this report records a regression signal rather than assigning a release-gate pass or fail.

## Interpretation limits and next action

This pair should not be cited as evidence of zero ordinary-path regression. It records a substantial increase in the existing area-light fixture costs. The snapshots isolate the changed file, but that file contains both clipping and evaluator/data-layout changes. The fixtures also contain a mixture of full-face and partially clipped receiver cases, so this diagnostic cannot separate clipping-only cost from overhead on fully front-facing area receivers.

The appropriate engineering follow-up is to examine the measured area-evaluator overhead before claiming acceptable CPU performance, and retain these artifacts as the pre-optimization comparison. Further runs are deliberately outside this worker’s authorized one-pair budget.

The host is shared and uncontrolled; frequency, thermal state, process placement, and other workers were not controlled. The run order was baseline then candidate, with only three samples and no confidence interval. The submillisecond point microbenchmarks and all p95 values are particularly sensitive to noise. These results are not physical-device, Metal/GPU, memory, thermal, sustained-frame-rate, or product release-gate evidence.
