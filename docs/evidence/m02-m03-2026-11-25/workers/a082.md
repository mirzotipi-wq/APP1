## Why this reaches the filesystem write path

`ProjectLibraryFileStore.save(_:replacing:)` first validates the candidate, loads and compares the prior snapshot under its lock, then encodes pretty/sorted JSON, enforces its 8 MiB application bound, and calls Foundation `Data.write(to:options: .atomic)` (`Sources/LightingCore/ProjectLibrary.swift`). Existing validation/cancellation-only receipts do not exercise a failure of that write.

The new probe uses deterministic UUIDs and ordinary valid scenes/names:

1. Unrestricted setup saves and reopens a three-project prior snapshot. It includes the active project, one unrelated open project, and one unrelated archived project. Exact bytes are preserved in `prior.json`.
2. The candidate edits the active project and adds ordinary projects up to the existing 64-project capacity. The existing two unrelated records remain unchanged. Candidate bytes are validated and encoded before injection, with runtime assertions that `prior bytes < 32 KiB < candidate bytes <= 1 MiB < the 8 MiB application limit`.
3. A separate unrestricted control process performs the real candidate save to an independent store initialized with the same prior snapshot. A failed control stops the experiment and cannot certify the injection.
4. Only the owned injection subprocess receives `RLIMIT_FSIZE=(32768, 32768)` and `SIGXFSZ=SIG_IGN` before exec. The Python parent keeps its limits and signal disposition unchanged. Child output uses pipes, so the file-size limit does not block its JSON report. No disk filling, mount, permission changes, root privileges, shared-process signals, or external process control are used.
5. That child validates/compares the exact prior bytes before calling the actual store save. Only an exception caught from that save is recorded as an injected save result. Success requires the returned NSError chain to contain `NSPOSIXErrorDomain` with the host's `errno.EFBIG`; validation, stale-snapshot, child setup, unexpected termination, or success cannot pass.
6. A distinct fresh process reopens both stores. It must find the entire prior library, active identity, both full unrelated records, and exact prior bytes intact in the failure store; the control must contain the entire candidate and exact candidate bytes. Python independently compares the persisted byte sequences and computes SHA-256 values.

Each child phase has a 30-second timeout. Timeout cleanup concerns only the process created by that invocation and is a failure, never interruption-test evidence. All generated probe artifacts remain in the caller's fresh output directory; fixed candidate/file bounds keep the normal output well below a few MiB. An existing output directory is rejected rather than overwritten.

## Root build/run instructions (not executed by a082)

Use the repository's existing standalone compilation pattern, selecting the known available Swift compiler if it is not on PATH. Run from the repository root after the source freeze. `probe_root` is a new caller-owned temporary directory, and `run` must not already exist.

```bash
probe_root="$(mktemp -d /var/tmp/keyfill-atomic-write.XXXXXX)"
swiftc -O Sources/LightingCore/*.swift scripts/probe-atomic-library-write.swift -o "$probe_root/probe-atomic-library-write"
python3 scripts/probe_atomic_library_write.py --helper "$probe_root/probe-atomic-library-write" --output "$probe_root/run" --source-revision "$(git rev-parse HEAD)"
```

On macOS, choose an available caller temporary parent such as `$TMPDIR` for `mktemp` if `/var/tmp` is unsuitable. The launcher uses only Python's standard POSIX `resource` and `signal` APIs and the Swift helper conditionally imports Glibc/Darwin. Linux and macOS execution remain **unverified by this worker**.

The launcher exits 0 only when every observed setup/control/EFBIG/reopen/byte-preservation check passes and the parent's limit/signal state is unchanged. Any failure exits 1 with JSON. The helper itself uses a distinct nonzero exit for preflight/setup/verification failures; a caught save error is reported as structured data for the launcher to classify.
