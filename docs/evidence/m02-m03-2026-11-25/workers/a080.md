# Worker 80 — discrete actions during plan drag

P2 static counterexample: a queued Undo callback can outlive its button's enabled state. Start with prior history; begin dragging selected light A; deliver Undo before the disabled UI prevents it. `undo()` only checks library busy (StudioView.swift:1165–1168), commits/undoes the history transaction, and preserves A's selection. It never clears `planDrag`. The next captured drag callback therefore reuses its original snapshot without `editHistory.begin` (1228–1244), mutating the restored scene outside history; ending the drag cannot record that mutation, and stale redo remains available. Redo has the same missing boundary. Guard history actions against active editing/dragging, or invalidate ongoing gesture callbacks when applying history.

Ordinary duplicate, remove, recipe replacement, and changed-selection paths preserve captured light identity; their selection change closes dragging, while `record(previous:)` preserves separate gesture/command undo entries.
