# Prototype 0.1 — native studio

This prototype is intended as a multi-project lighting editor prototype on iOS 17+. It is not a release candidate.

- Choose one of four editable portrait recipes, select lights in the plan or rack, edit position, intensity and temperature, add/remove lights, undo/redo and save.
- Switch Plan / 3D / Camera to inspect illustrative geometry in a native SceneKit viewport; tap the camera marker to edit its position and 14–200 mm full-frame lens. Coverage and field-of-view values use the tested ideal projection model.
- Choose bare point, directional or rectangular softbox, adjust aim target and modifier dimensions, view ideal direct lux on the camera-facing subject plane. Overhead view displays aim and footprints. Source types and lens settings participate in undo/redo and versioned local saves.
- Open Light meter & test card for combined direct lux, ideal 18% neutral-card color, balance and relative exposure. Controls change the diagnostic card only, not SceneKit shading.
- The intensity mapping is artistic; it is not calibrated. SceneKit is a temporary adapter; production RealityKit/Metal remains the target.
- Use the share menu for text settings or a native vector PDF lighting plan. Choose A4 or US Letter and metric or imperial units; preview the document, then share. Export does not save or mutate the project and includes no reference photo. Earlier native PDFKit and PDF preview tests passed; current share/open and screenshot review remain pending. Corrupt saved data blocks writes.
- Save the initial setup, then open Projects. Create a named portrait project, rename or duplicate saved scenes, open another project, or archive an inactive one and restore it later. Save current edits before changing projects; a switch resets the editor history. Legacy portrait.json is preserved when migrated. If a different window changes the library, save the current setup as a separate recovery project without replacing the newer record, or explicitly confirm reloading and discarding this window's edits. Failed recovery operations preserve in-memory edits. Capacity is 64 projects including archived; remove an archived project after explicit destructive confirmation to free a slot. The active and unarchived projects are protected. Removal is permanent within the current library, not secure erasure; migrated legacy portrait.json and external exports are retained. If existing data cannot be opened, the editor shows a protected-data error and Retry rather than allowing replacement or exporting a default scene. Native verification remains pending.
- Charcoal workspace, amber selection, one-meter grid, readable system surfaces, visible units, native navigation and accessibility labels.

Open Actions > iOS Prototype. The Ubuntu job runs portable debug/release tests and native Swift syntax parsing; the macOS job retains package tests, generates the Xcode project, builds unsigned Debug and Release simulator configurations, runs UI smoke and exports XCTest attachments and logs. Download the simulator app artifact after a successful build; unzip the archive and use xcrun simctl install booted KeyAndFill.app.

The simulator app is not a signed IPA. A prior unsigned Debug build succeeded; current native build and UI smoke are unverified until CI completes. Reference inference, calibrated rendering, AR, current native PDF and project library UI verification, deletion/recovery and privacy validation, commerce, manual accessibility and real-device tests remain outstanding.


### Numerical lighting study
Choose Study to render a neutral sphere and panel from the current camera. Emitter geometry, aiming, finite-source visibility, output, color temperature, relative white balance/exposure and lens affect the image. This is an ideal diagnostic direct-light simulation, not a calibrated portrait or camera exposure. The backend label identifies CPU reference or Metal compute. A device must pass six runtime parity fixtures before Metal is selected; CPU fallback remains available. Unsupported surface samples are marked magenta and counted. Native UI execution is pending.

### Manual room placement

Choose Room placement from the studio. Enter the measured room width/depth (1–30 m), subject floor offsets from the left and near walls, and rig yaw. Set each numeric entry explicitly; invalid drafts leave previous values unchanged. The map is an overhead 1:1 coordinate transform of equipment centers. Signed X/Z coordinates, light/camera height and horizontal subject distance are listed; out-of-room centers are flagged without clamping. This does not sense the real room, estimate footprints or ensure collision, cable or ceiling clearance. Room parameters are session-only; the studio scene, undo history and saved project remain unchanged. Native UI and physical verification are still required; this is not AR.
