# Prototype 0.1 — native studio

This prototype is intended as a multi-project lighting editor prototype on iOS 17+. It is not a release candidate.

- Choose one of four editable portrait recipes, select lights in the plan or rack, edit position, intensity and temperature, add/remove lights, undo/redo and save.
- Switch Plan / 3D / Camera to inspect illustrative geometry in a native SceneKit viewport; tap the camera marker to edit its position and 14–200 mm full-frame lens. Coverage and field-of-view values use the tested ideal projection model.
- Choose bare point, directional or rectangular softbox, adjust aim target and modifier dimensions, view ideal direct lux on the camera-facing subject plane. Overhead view displays aim and footprints. Source types and lens settings participate in undo/redo and versioned local saves.
- Open Light meter & test card for combined direct lux, ideal 18% neutral-card color, balance and relative exposure. Controls change the diagnostic card only, not SceneKit shading.
- The intensity mapping is artistic; it is not calibrated. SceneKit is a temporary adapter; production RealityKit/Metal remains the target.
- Use the share menu for text settings or a native vector PDF lighting plan. Choose A4 or US Letter and metric or imperial units; preview the document, then share. Export does not save or mutate the project and includes no reference photo. Earlier native PDFKit and PDF preview tests passed; current share/open and screenshot review remain pending. Corrupt saved data blocks writes.
- Choose Export → Editable project copy to preserve the current setup, including unsaved edits, as a bounded JSON document. This remains available when all 64 project slots are occupied. Projects → Import editable project validates a selected copy and creates a separate project with a fresh identity; save current edits and free a slot first. Copies include the project name and scene settings, not reference photos, room measurements or undo history. File export, provider import and cancellation require current native verification.
- Save the initial setup, then open Projects. Create a named portrait project, rename or duplicate saved scenes, open another project, or archive an inactive one and restore it later. Save current edits before changing projects; a switch resets the editor history. Legacy portrait.json is preserved when migrated. If a different window changes the library, save the current setup as a separate recovery project without replacing the newer record, or explicitly confirm reloading and discarding this window's edits. Failed recovery operations preserve in-memory edits. Capacity is 64 projects including archived; remove an archived project after explicit destructive confirmation to free a slot. The active and unarchived projects are protected. Removal is permanent within the current library, not secure erasure; migrated legacy portrait.json and external exports are retained. If existing data cannot be opened, the editor shows a protected-data error and Retry rather than allowing replacement or exporting a default scene. Native verification remains pending.
- Charcoal workspace, amber selection, an adaptive grid with explicit meter spacing, readable system surfaces, visible units, native navigation and accessibility labels. Fit setup centers the actual equipment bounds in plan and resets the 3D orbit on request; ordinary 3D edits preserve the current orbit.

## Build and verification

Open Actions > iOS Prototype. The Ubuntu `core` job runs portable Debug/Release tests, record/shard checks, native Swift syntax parsing, reference rendering and shared-kernel checks. The macOS `simulator` job runs the portable package, generates the Xcode project, builds unsigned Debug and Release simulator configurations, and runs the native unit target. A separate UI matrix builds and tests three shards: `room-precision`, `library-reference`, and `studio-export`. All six UI test classes are assigned once across those shards. Native jobs check the Metal compiler before building and retain logs plus finalized XCTest results and genuine attachments when available. Inspect each job at the exact source revision; a successful build or one completed shard does not establish a complete native pass.

Download a simulator app artifact after its build succeeds; unzip the archive and use `xcrun simctl install booted KeyAndFill.app`. These artifacts are for simulator installation. Signed device/distribution builds require separate evidence. Native Swift syntax parsing alone cannot verify Apple SDK APIs or UI behavior. Current acceptance depends on the actual completed results recorded in the [handoff](../agents/HANDOFF.md) and [evidence](../agents/evidence.json); this guide makes no current CI pass claim. Reference inference, calibrated rendering, AR, current native PDF/share and project-library UI verification, deletion/recovery and privacy validation, commerce, manual accessibility and real-device tests remain outstanding.

### Precise numeric editing

Tap a numeric value or its pencil icon to enter an explicit value within the displayed range. Readouts and slider accessibility values retain the stored value's digits, including signed values smaller than one millionth; they are not snapped to slider increments. Digits and decimal separators follow the current locale. Values that would need an excessively long decimal readout use bounded scientific notation with `e`.

The editor starts with an exact decimal draft when it fits the supported entry length. For an extreme imported value that cannot fit, the sheet shows its current scientific value and an empty replacement field. Leave that field empty and apply to preserve the original, or enter a new decimal value. Cancel and applying an untouched draft preserve the stored value. Input remains limited to decimals within the stated range, without grouping or scientific notation. Displayed precision does not establish physical measurement accuracy; current keyboard behavior and VoiceOver pronunciation still require native/device verification.

### Numerical lighting study

Choose Study to render a neutral sphere and panel from the current camera. Emitter geometry, aiming, finite-source visibility, output, color temperature, relative white balance/exposure and lens affect the image. This is an ideal diagnostic direct-light simulation, not a calibrated portrait or camera exposure. The backend label identifies CPU reference or Metal compute. Unsupported surface samples are marked magenta and counted.

Metal must pass all six raw runtime parity fixtures, including the deliberately unsupported near-field fixture, before it becomes available. Production rendering then makes a conservative choice for each scene: geometry outside the relative-distance domain or close to ambiguous source/surface cutoffs uses the Double CPU reference. That scene-specific choice leaves a validated Metal backend available for a later eligible scene. The guard uses the actual sphere, rectangular emitting faces and visible panel; it can choose CPU for additional conservative cases. Its margin is an engineering safeguard, not a universal GPU error bound or physical calibration. The validation path sends all six fixtures to the raw GPU kernel; production CPU routing does not substitute CPU results for that check. Actual current Metal execution, UI behavior and physical-device performance remain separate verification requirements.

### Manual room placement

Choose Room placement from the studio. Enter the measured room width/depth (1–30 m), subject floor offsets from the left and near walls, and rig yaw. Press Set for each changed measurement; invalid drafts leave the committed layout unchanged. The map is an overhead 1:1 coordinate transform of equipment centers. Signed X/Z coordinates, light/camera height and horizontal subject distance are listed; out-of-room centers are flagged without clamping.

Rectangular modifiers also show projected emitting-face outlines. The app reports a wall crossing when that projection extends outside the room, even if its center remains inside, and shows calculated wall distance or overhang. A projection with an invalid aim is marked unavailable. These checks cover equipment centers and ideal rectangular emitting faces only. Complete fixtures, stands, booms, cables and ceiling clearance still need physical inspection; the app does not sense the room or perform full collision checking.

Choose **Review and share notes** to preview a text snapshot of the committed room dimensions, subject offsets, rig rotation, numbered equipment measurements and placement/projection warnings. The preview and share action use the same captured text. Press Set before opening the notes to include a changed entry; an unfinished draft is not exported. Room parameters remain session-only and are not included in saved lighting projects or editable project copies. Sharing these separate notes preserves the measured layout without changing the studio scene or undo history. Native UI/share and physical verification remain required; AR tracking is not implemented.
