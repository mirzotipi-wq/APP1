# Prototype 0.1 — native studio

This iOS 17+ lighting editor is an engineering candidate, not a release candidate. Use the [beta tester guide](BETA_TESTER_GUIDE.md) for current control paths and the [live campaign packet](evidence/beta-campaign-2026-11-27/README.md) for revision-specific results and pending checks.

- Choose one of four editable portrait recipes, select lights in the plan or rack, edit position, intensity and temperature, add/remove lights, undo/redo and save.
- Switch Plan / 3D / Camera to inspect the overhead plan, RealityKit studio (SceneKit on Intel simulators) and SceneKit camera preview; tap the camera marker to edit its position and 14–200 mm full-frame lens. Coverage and field-of-view values use the tested ideal projection model.
- Choose bare point, directional or rectangular softbox, adjust aim target and modifier dimensions, view ideal direct lux on the camera-facing subject plane. Overhead view displays aim and footprints. Source types and lens settings participate in undo/redo and versioned local saves.
- Open Light meter & test card for combined direct lux, ideal 18% neutral-card color, balance and relative exposure. These controls affect the card and Study viewport; illustrative 3D shading remains separate.
- Preview shading is illustrative and uncalibrated. Numerical lighting studies use a separate CPU/optional Metal path.
- Use the share menu for text settings or a native vector PDF lighting plan. Choose A4 or US Letter and metric or imperial units; preview the document, then share. Export does not save or mutate the project and includes no reference photo. Earlier native PDFKit and PDF preview tests passed; current share/open and screenshot review remain pending. Corrupt saved data blocks writes.
- Choose Export lighting plan → Editable project copy to preserve the current setup, including unsaved edits, as a bounded JSON document. This remains available when all 64 project slots are occupied. Projects → Import editable project validates a selected copy and creates a separate project with a fresh identity; save current edits and free a slot first. An untouched first-use starter need not be saved before import. Copies include the project name, scene settings and committed room measurements; photographs and undo history are excluded. File export, provider import and cancellation require current native verification.
- On an untouched first-use setup, save the starter or open Projects to create/import a project directly. Create a named portrait project, rename or duplicate saved scenes, open another project, or archive an inactive one and restore it later. Save current edits before changing projects; a switch resets the editor history. Legacy portrait.json is preserved when migrated. If a different window changes the library, save the current setup as a separate recovery project without replacing the newer record, or explicitly confirm reloading and discarding this window's edits. Failed recovery operations preserve in-memory edits. Capacity is 64 projects including archived; remove an archived project after explicit destructive confirmation to free a slot. The active and unarchived projects are protected. Removal is permanent within the current library, not secure erasure; migrated legacy portrait.json and external exports are retained. Unreadable saved data blocks normal writes and export; Retry and an explicitly confirmed preservation/recovery flow are available. Native verification remains pending.
- Charcoal workspace, amber selection, an adaptive grid with explicit meter spacing, readable system surfaces, visible units, native navigation and accessibility labels. Fit setup centers the actual equipment bounds in plan and resets the 3D orbit on request; ordinary 3D edits preserve the current orbit.

## Build and verification

Open Actions > iOS Prototype. The Ubuntu `core` job runs portable Debug/Release tests, record/shard checks, native Swift syntax parsing, reference rendering and shared-kernel checks. The macOS `simulator` job runs the portable package, generates the Xcode project, builds unsigned Debug and Release simulator configurations, and runs the native unit target. The required UI matrix covers `room-precision`, `library-reference`, `studio-export`, `studio-optics` and `app-accessibility`; Apple's full accessibility audits are separate opt-in diagnostics. Native jobs check the Metal compiler before building and retain logs plus finalized XCTest results and genuine attachments when available. Inspect each job at the exact source revision; a successful build or one completed shard does not establish a complete native pass.

Download a simulator app artifact after its build succeeds; unzip the archive and use `xcrun simctl install booted KeyAndFill.app`. These artifacts are for simulator installation. Signed device/distribution builds require separate evidence and owner approval. Native Swift syntax parsing alone cannot verify Apple SDK APIs or UI behavior. Current acceptance depends on the actual completed results recorded in the [handoff](../agents/HANDOFF.md) and [evidence](../agents/evidence.json); this guide makes no current CI pass claim. Held-out reference evaluation, calibrated rendering, current native PDF/share and project-library UI verification, deletion/recovery and privacy validation, commerce, manual accessibility and physical AR/device tests remain outstanding.

### Precise numeric editing

Tap a numeric value or its pencil icon to enter an explicit value within the displayed range. Readouts and slider accessibility values retain the stored value's digits, including signed values smaller than one millionth; they are not snapped to slider increments. Digits and decimal separators follow the current locale. Values that would need an excessively long decimal readout use bounded scientific notation with `e`.

The editor starts with an exact decimal draft when it fits the supported entry length. For an extreme imported value that cannot fit, the sheet shows its current scientific value and an empty replacement field. Leave that field empty and apply to preserve the original, or enter a new decimal value. Cancel and applying an untouched draft preserve the stored value. Input remains limited to decimals within the stated range, without grouping or scientific notation. Displayed precision does not establish physical measurement accuracy; current keyboard behavior and VoiceOver pronunciation still require native/device verification.

### Numerical lighting study

Choose Study to render a neutral sphere and panel from the current camera. Emitter geometry, aiming, finite-source visibility, output, color temperature, relative white balance/exposure and lens affect the image. This is an ideal diagnostic direct-light simulation, not a calibrated portrait or camera exposure. The backend label identifies CPU reference or Metal compute. Unsupported surface samples are marked magenta and counted.

Metal must pass all six raw runtime parity fixtures, including the deliberately unsupported near-field fixture, before it becomes available. Production rendering then makes a conservative choice for each scene: geometry outside the relative-distance domain or close to ambiguous source/surface cutoffs uses the Double CPU reference. That scene-specific choice leaves a validated Metal backend available for a later eligible scene. The guard uses the actual sphere, rectangular emitting faces and visible panel; it can choose CPU for additional conservative cases. Its margin is an engineering safeguard, not a universal GPU error bound or physical calibration. The validation path sends all six fixtures to the raw GPU kernel; production CPU routing does not substitute CPU results for that check. Actual current Metal execution, UI behavior and physical-device performance remain separate verification requirements.

### Manual room placement

Choose Room placement from the studio. Enter the measured room width/depth (1–30 m), optional ceiling height, subject floor offsets from the left and near walls, and rig yaw. Press Set for each changed measurement; unfinished or invalid field text leaves the committed layout unchanged. If the displayed values already match the room, choose **Keep room with setup**. Applied room changes participate in studio undo/redo; choose **Save** in the studio to retain them for future sessions. Committed measurements are included in editable JSON copies, PDF plans and text settings.

The map applies an overhead 1:1 coordinate transform to equipment centers and rectangular emitting-face outlines. Signed wall coordinates, height and horizontal subject distance are listed; out-of-room centers are flagged without clamping. A rectangular face can cross a wall even when its center is inside; invalid aim makes its projection unavailable. Height checks cover a flat floor and, when measured, a flat ceiling. Complete fixtures, stands, booms, cables and working clearance still need physical inspection; the app does not sense the room or perform full collision checking.

Choose **Review and share notes** to preview a text snapshot of the committed room dimensions, subject offsets, rig rotation, equipment measurements and placement warnings. The preview and share action use the same captured text; unfinished field drafts are excluded. Sharing notes does not save the project or change undo history. **Remove room from setup** asks for confirmation; save afterward to retain the removal. Native UI/share and physical verification remain required.

### AR placement

Open **Studio tools → Place in AR → Start AR camera**. On supported physical devices, ARKit world tracking and RealityKit place the authored setup at 1:1 scale after camera permission. Aim at the physical floor and choose **Place subject on this floor point**, then adjust **Setup direction**. Tracking guidance, recovered-placement review, **Reset and scan again** and **Stop camera** are implemented. Use **Use manual room measurements** when AR is unavailable or unsuitable; the simulator cannot place a setup in a real room.

Displayed distances come from the authored plan, not measurements of real equipment or tracking accuracy. Camera frames and world maps are not saved; anchors clear when leaving or pausing the camera. Physical-device placement accuracy, interruption/recovery and privacy acceptance remain unverified.
