## Minimal invariants

- Validate before changing scene, selection, revision, history, or the enclosing receipt-operation state. Invalid candidates leave the complete state equal, including open transaction ownership and redo.
- Supported schemas 1–5 migrate only their version; preserve UUIDs, SI values and stored optional representations. Reject duplicate IDs, unsupported versions, nonfinite values, and fields introduced after a candidate's schema. `Scene.swift:62–80` satisfies these by inspection; continuous optional restoration is the deliberate exception (`SceneEditHistory.swift:33–57`).
- Reset adoption clears past/future/open gesture, chooses a live first-light selection (nil when empty), and retires revision even for equal content. Non-reset adoption preserves the complete editor and must not apply another scene. First-save project identity remains outside the scene.
- Failed feature validation must not call `didApply`; successful own changes alone may advance accepted revision (`StudioFeatureContext.swift:34–41`).

## Findings and actions

**P2 — Non-reset adoption can splice unrelated scenes into retained history.** `StudioEditorState.swift:101–112` accepts changed valid content without recording it, clearing redo, or replacing a pending transaction start. Reproduction: replace A→B; undo to A; adopt C with `resettingHistory:false`; redo restores B over C. Alternatively begin at A, update B, adopt C, cancel: C is discarded for A. No-reset receipt producers already return `currentScene` (`App/ProjectLibraryOperation.swift:119–125`). Smallest enforcement: reject differing validated content with a dedicated adoption error, before any mutation; retain equal-content no-op behavior. Root accepted this finding for implementation. No fix or regression was present or tested in this frozen worktree.

**Integration requirement — commit receipt and editor atomically.** Operation adoption changes generation/pending (`App/ProjectLibraryOperation.swift:133–134`); editor adoption can subsequently throw (`StudioEditorState.swift:102`). A receipt containing duplicate light IDs falsifies atomicity if these mutate live values sequentially. Validate/stage both copies before committing either. Root reports its concurrent composition follows that approach; this worker has not inspected or verified that later revision.

Targeted verification for integration: invalid update/adopt under both reset policies with redo plus an open gesture; compare whole editor before/after. Add changed-valid no-reset rejection and equal no-reset preservation; loop supported schemas with stable IDs/optionals; reset-equal must retire revision and clear all history. Existing frozen tests cover invalid replace only (`StudioEditorStateTests.swift:5–11`) and equal save/reload (`92–107`), leaving these direct boundary cases uncovered.
