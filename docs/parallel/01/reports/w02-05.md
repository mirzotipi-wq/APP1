## Minimal owning contract

One live stored session owns admission, application, receipt advancement and retirement. Closures capture context only. Check that live session’s owner/generation/revision/busy state, validate/apply synchronously, then advance only that same owner’s receipt. F41’s public `didApply` proves no provenance itself: never advance it from a general scene-change observer. Example: A accepts r0→r1; unrelated edit creates r2; copying r2 into A would wrongly admit A’s next stale result.

Retire A synchronously when close/replacement begins; do not wait for animated `onDismiss`. A delayed A dismissal must neither retire B nor end B’s editing transaction. Require captured-owner equality before clearing the live session, and pass A’s owner when ending its edit (the existing room pattern at V1243–1261, 1283–1293 is useful).

For a valid same-scene result, return acceptance `true` even though E40/E54 returns mutation `false`; leave the revision unchanged. Validation failure must neither advance the receipt nor mutate history. A valid no-op still requires admission first, so dismissed/stale callbacks cannot succeed merely because their proposed content matches.
