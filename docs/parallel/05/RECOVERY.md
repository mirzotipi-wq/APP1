# Environment interruption and recovery

The Linux execution environment became unavailable during wave 02. A Swift test rebuild ended with `emit-module command failed due to signal 9` before executing tests; subsequent exec requests failed with a disconnected exec-server and a 45-second recovery timeout. The environment then explicitly reported unavailable. No cause beyond those observed facts is asserted.

Published source `68c83cca75f9ef8fd41fe6a33358b00e0790c45a` and its exact tree `eba89a0fc2a4e500c40404235ba5fe96b672d871` were verified remotely before the outage. The source snapshot was also retained in the coordinator's code-mode store. Follow-up code was recovered from that exact snapshot and the recorded patch operations, using cardinality-checked replacements. Only this lane's branch is updated; no main or other branch is modified.

The follow-up extends far clipping to the full diagonal between the bounded pan target and authored world, and includes the selected aim-target sphere in App-only viewport bounds. RealityKit consumes the same 55 mm marker diameter. Two regressions cover these cases. The far-clip version had nine actual passing portable XCTest methods before the outage. The later ten-test marker version compiled its source and test modules, then its generated test-runner module was killed; it has no local test pass. The saved failure excerpt is exact observed tool output, not a complete recovered raw log.

For the first published source, eight actual portable helper tests passed (source SHA256 `1c11491da72e71671ca819ec45c642e00ca9f834b421b61858e7ac97027e830f`, test SHA256 `851acd34da7b4046c9db4fde57fbd6d70a4e248e589b1ffa996fb17ad97afb40`). The private package copied the production helper and changed only the XCTest module import from KeyAndFill to SpatialViewport. Swift 6.0.3 Linux, one build job. Apple adapters were only parsed locally. Current GitHub core job139899956548/run45817222487 passed 366 Debug and 366 Release package tests plus100 tooling checks; its complete retrieved log is retained. Apple runtime results must be recorded separately at their exact SHA.

Wave01 completed ten fresh contexts. Its original reports existed in temporary storage and were copied into the local checkout before the outage but were not yet published. Recoverable agent responses are retained separately and must not be described as full raw report recovery. Wave02 continued source-only through the GitHub connector with per-worker input SHAs. No temporary worktree, local build or capture was fabricated while the environment was unavailable.

The environment subsequently returned with empty temporary storage. A fresh sparse checkout recovered commit `9218740173e718efe928ee18dfe5da844c2f2179` from GitHub. SHA256 comparison exactly matched the last pre-outage source and test files: helper `008f231e3c9d5491dd36c27df025de0c70d68cb947fb6ed0e3a88ee77e0a49eb`, tests `b84f03da51c0833a9de9f7579d0117129500fba77d763718d3f6fbffe90af5a4`. Thus both latest source files were recovered byte-for-byte; unpublished raw worker reports and local build outputs were not recovered. Later changes have their own revisions and evidence.

## Second temporary-storage restart

During wave 04, the executor restarted again and temporary storage disappeared. The source and complete waves 01–03 evidence had already been published at `9725fb1177a5c7afbdf798ffd627e65e604c75b1`. A fresh sparse clone recovered the exact tree `4bb153424aa9b20efb1d7bc8f89e6b6b1c1be2fb` with a clean working directory. The two original capture digests were verified again. The unpublished local `956a3b1` commit object was lost; subsequent worker reads use published `9725fb1`, whose production/native source is identical. Original pre-restart read provenance is retained separately. Wave 04 report files that had not been published are reconstructed from worker-returned text and explicitly labeled where applicable. No source work or completed three-wave bundle was lost in this restart.
