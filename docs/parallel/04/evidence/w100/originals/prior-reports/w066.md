## Ownership finding

The [engine](https://github.com/mirzotipi-wq/APP1/blob/240000fd3f8cb75273eb279be9dcc7f204a5b29f/App/MetalStudyRenderer.swift), blob `8c1acd852d85cd99671feaba883db1808bbb5e68`, constructs the default backend inside the actor. The renderer owns its device, queue and pipeline; the factory captures no renderer. Startup holds only a local backend until validation and its final cancellation check succeed. Interrupted validation never adopts that instance. Confirmed failure selects CPU before a subsequent cancellation check, and the failed local reference unwinds. CPU-only requests do not initialize Metal.

Submitted commands explicitly finish through `waitUntilCompleted()`; status is checked before cancellation, and output is copied into `Data` before the autorelease pool returns. Cached `StudyRenderedFrame` values contain image data and a backend label, with no renderer/Metal references. This is source ownership analysis, not a measurement of driver allocation reclamation or an assertion about default command-buffer retention semantics.
